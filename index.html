Never used a database? Start here.

What Postgres is. A program that stores tables and answers questions about them. A table is rows and columns, much like a spreadsheet, except the rules about what may go in each column are enforced rather than hoped for. Postgres began at Berkeley in 1986, so it is neither new nor a new kind of thing. Everyone is building on it now because it is old, free, and has stopped surprising people.

What the questions look like. You ask in SQL, a language designed to read almost like English: select name from vendors where owner = 'Amazon'. Six lessons below take you from nothing to reading that comfortably.

No experience assumed

Everything runs against the real database on this page, so nothing can break and nothing is being saved. Get something wrong and Postgres tells you why. That is the fastest way to learn it.

The Theory

Read it. Running anything is optional.

Codd published twelve rules in Computerworld in October 1985, defining what a database must do to call itself relational. Forty years on they remain the sharpest available test, and almost uniquely among foundational texts they can be checked against a running system rather than argued about. Each rule below is stated in our own words, judged, and backed by a demonstration you can run against the Postgres on this page if you want to. The verdict is the point; the SQL is evidence, folded away.

Three of the twelve fail or partly fail, and those are the interesting ones. Where SQL departs from the relational model, it departs deliberately, and the departures have consequences you meet in production.

Reading the sources. The ACM Digital Library became fully open access on 1 January 2026, so Codd's papers are now free to read. Start with A Relational Model of Data for Large Shared Data Banks (CACM 13(6), 1970) at doi.org/10.1145/362384.362685. For rule 3 specifically, Missing Information (Applicable and Inapplicable) in Relational Databases (SIGMOD Record 15, 1986) is the argument he made when SQL had already gone the other way. The twelve rules themselves appeared in trade press rather than in ACM, and are restated here rather than reproduced.

The Floor

Portable · transfers to every vendor

Free-weight work. Everything here is ANSI SQL or core Postgres, so it survives a migration from Neon to Supabase to Aurora to a box under your desk. Each drill shows a worked example you can run, then sets a related task. The checker compares your result against a reference answer — any query that returns the right rows passes.

About the seed data. Two tables, vendors and rounds, holding the database market itself as reported on 27 July 2026. Only figures stated in the source reporting are present; everything undisclosed is NULL rather than guessed. Half the difficulty in real SQL comes from missing values, so the drills lean into it.

The Machines

Vendor-specific · check the transfer rating

Each machine trains one thing well and holds part of your work captive. The transfer rating estimates how much of what you learn and build survives a move to a different supplier: blue leaves with you, magenta stays behind. Ratings are editorial judgements about query-language portability and migration cost, not vendor claims.

The Spotters

Which AI platform reaches which database

Vercel gave up running its own storage and became a broker, provisioning other people's databases from inside its marketplace. It has company. Three patterns dominate: a platform ships one database and hides the wiring (native), a coding agent talks to whatever you own through Model Context Protocol (MCP), or you paste a connection string yourself (BYO).

AI platformReachesHowWhat it means for you
Read the MCP row carefully. An agent with write access to a production database is a new class of hazard. Every serious database MCP server ships a read-only mode; start there, scope credentials to one project or schema, and grant writes only against a database you can restore.

What this prototype is

A working skeleton: real Postgres in the browser via PGlite, eight drills with automatic checking, fourteen platform cards, and a connection matrix. Curriculum, accounts, and progress persistence are not built. Vendor facts carry a date and will rot — pricing, ownership and feature claims in this market change monthly.
